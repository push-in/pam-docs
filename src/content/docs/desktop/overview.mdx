**Desktop software that feels like PHP.** PAM Desktop keeps your application
alive in typed PHP, renders trusted local
HTML and CSS directly with Servo, and puts Rust in charge of every native
boundary. You get web-speed authoring without an Electron-sized Node runtime
or ambient access to the machine.

```php
#[Desktop(id: 'com.example.notes', name: 'Notes')]
final class NotesApp extends App
{
    #[Command]
    public function save(
        DocumentData $document,
        DocumentRepository $documents,
        WindowHandle $window,
    ): DocumentResource {
        $saved = $documents->save($document);
        $window->title("Saved · {$saved->title}");

        return new DocumentResource($saved);
    }
}
```

No payload plumbing. No hand-built response envelope. No effect tree in your
use case. PHP types describe the command; PAM binds input, resolves services,
collects native effects, and returns the result.

## Start in three commands

<Steps>
1. Create the project.

   ```bash
   pam init hello-desktop --template desktop
   cd hello-desktop
   ```

2. Validate the host and project.

   ```bash
   pam desktop doctor .
   ```

3. Start the persistent development session.

   ```bash
   pam desktop dev .
   ```
</Steps>

Edit PHP, HTML, CSS, or JavaScript and save. PAM replaces the development
worker or rendering generation safely while preserving what can survive the
change.

## The application model

The class-level `#[Desktop]` attribute describes stable product metadata and
the main window. Methods marked `#[Command]` become frontend-callable use
cases. Dependencies come from the application container; input comes from the
command payload by parameter name.

```php
#[Desktop(
    id: 'com.pushin.my-app',
    name: 'My desktop app',
    version: '1.0.0',
    description: 'A PHP-first native desktop application.',
    category: ApplicationCategory::Development,
    theme: WindowTheme::Dark,
)]
final class MyApp extends App
{
    #[Command]
    public function greet(
        WindowHandle $window,
        Events $events,
        string $name = 'world',
    ): array {
        $window->title("Hello, {$name}");
        $events->emit(new GreetingCompleted($name));

        return ['message' => "Hello, {$name}!"];
    }
}
```

The entry point is deliberately boring:

```php
App\MyApp::run();
```

<Aside type="note" title="Same mental model as PAM Native">
  PAM Native uses classes, attributes, typed state, and injected platform
  services. PAM Desktop follows that authoring philosophy while exposing
  desktop-specific concepts: windows, tray, menus, files, processes, SQLite,
  and secure host capabilities.
</Aside>

## What ships today

- stable public PHP API 1, worker protocol 6, and Rust plugin protocol 1;
- Linux x86-64 releases built on the Ubuntu 22.04 glibc baseline;
- direct Servo rendering in independent native Winit windows;
- typed commands, DTOs, events, listeners, effects, deadlines, and cancellation;
- supervised stateful and parallel PHP workers with crash recovery;
- named filesystem, SQLite, HTTPS, process, secret, and portal capabilities;
- menus, tray, global shortcuts, background jobs, and lifecycle activation;
- process-isolated Rust plugins and composable PHP plugins;
- reproducible archives, per-file integrity, signed updates, and rollback; and
- diagnostics and repeatable bridge benchmarks.

Windows and macOS remain outside the current build and support contract.
