---
title: Roadmap
description: What PAM intends to stabilize and implement next.
---

The roadmap records direction, not a delivery guarantee. Items stay marked as planned until an executable contract and documentation exist.

## Runtime

- Stabilize the public server and package APIs toward `1.0`.
- Expand real-world compatibility fixtures and long-duration memory testing.
- Broaden supported distribution targets while retaining reproducible bundles.
- Deepen production guidance from deployed workloads.

## Laravel

- Continue the maintained Laravel 12 and 13 executable matrix.
- Track upstream package constraints without bypassing them.
- Expand package-specific persistence and worker-isolation evidence.
- Preserve the one-request-per-worker safety rule until the framework contract supports stronger concurrency.

## Native mobile

- Design and implement an iOS host and renderer.
- Establish iOS packaging, signing, device testing, and compatibility gates.
- Complete component, navigation, accessibility, and performance parity evidence.
- Grow the native plugin ecosystem with reviewed examples.

## Mobile UI

- Move individual components through maturity and verification gates.
- Fill incomplete behavior and accessibility evidence.
- Keep the machine-readable parity contract aligned with documentation.
- Define cross-platform visual behavior when an iOS renderer exists.

## Desktop

| Milestone | Scope |
| --- | --- |
| 0.5 | Windows and macOS, signing, and automatic updates |
| 0.6 | PHP/Rust plugins, menus, tray, global shortcuts, and background jobs |
| 1.0 | Stable API, compatibility suite, and multi-platform distribution |

## Suggest or own an item

Start with [Contributing](/community/contributing/). A useful proposal explains the current limitation, the smallest safe contract, how it will be tested, and which documentation will change.
