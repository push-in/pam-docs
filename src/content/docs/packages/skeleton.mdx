The `push-in/pam-skeleton` repository is the versioned source used by PAM to
generate a clean API application. Do not clone it for normal development; let
the CLI select the release compatible with your runtime.

```bash
pam init my-api --template api
cd my-api
pam doctor
pam dev index.php
```

The server starts at `http://127.0.0.1:3000`. Set `PAM_PORT` to select another
listener port.

:::caution[PAM API 2 development line]
This structured skeleton targets PAM API 2.0. Use the published 1.x skeleton
until the 2.0 prerelease is available on Packagist.
:::

## What the generated project contains

- `GET /api/ping` mapped to `[PingController::class, 'show']`;
- a thin controller, readiness service, readonly snapshot and JSON Resource;
- a sequential integer-backed `ReadinessStatus` enum;
- boot-time typed `PAM_PORT` validation;
- security-header middleware;
- an in-memory application test using the PAM API test client;
- standard Composer metadata, scripts, autoloading and lockfile behavior.

The CLI embeds these canonical skeleton files at build time. CI generates a
fresh project, performs a Composer dry-run, installs the local PAM API 2.0
candidate and executes the endpoint test inside the Embed SAPI, preventing the
published skeleton and `pam init` output from drifting apart.

API and skeleton releases are intentionally ordered. PAM API 2 must first pass
its public Packagist installation gate. The skeleton can then receive its own
2.0 tag and repeat the same clean-consumer dry-run and installation proof; the
native PAM runtime does not need a matching major version.

## Daily workflow

```bash
pam dev index.php
pam test
pam composer test
pam doctor
pam info --json
```

`pam dev index.php` runs the persistent server with hot reload. `pam test`
selects contextual project tests, while `pam composer test` explicitly invokes
the Composer script. `pam info --json` exposes machine-readable project
discovery for tooling and CI.

## Add capabilities

```bash
pam init realtime-api --template api --socket
pam add observability
pam doctor
```

Use `pam packages` to discover official capabilities. PAM performs metadata
lookup and a non-mutating compatibility preflight before changing the project.

## Release checklist

```bash
pam release --check
pam package
```

Configure listener limits, trusted proxies and TLS termination; exercise error,
timeout and shutdown paths; keep secrets outside version control; and test the
packaged artifact in its target environment.
