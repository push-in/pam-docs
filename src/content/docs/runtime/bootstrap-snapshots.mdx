---
title: Signed bootstrap snapshots
description: Freeze, sign, verify, and run the exact PHP source tree expected by a PAM production cold start.
---

PAM source snapshots freeze the PHP tree expected at cold start. Before the
Embed SAPI starts, PAM hashes every tracked PHP file, validates runtime and ABI
compatibility, and rejects additions, removals, or mutations. Reading the tree
also warms the operating-system page cache for the following boot.

This is a source snapshot, not a serialized Zend VM heap. It never captures
native resources, credentials, database handles, request state, or user data.

## Create, verify, and run

```bash
pam snapshot create \
  --entry public/index.php \
  --signing-key /run/release/pam-ed25519.pem

pam snapshot verify .pam/bootstrap.snapshot.json \
  --public-key /etc/pam/release.pub \
  --require-signature

pam snapshot run .pam/bootstrap.snapshot.json \
  --public-key /etc/pam/release.pub \
  --require-signature
```

`run` completes verification before application PHP executes. Add `--`
followed by application arguments when needed.

The deterministic manifest contains schema version, exact PAM runtime and
native ABI, relative entry point, sorted PHP paths, byte lengths, SHA-256
digests, and optional Ed25519 public-key identity and sidecar signature.

Signed snapshots require an externally trusted public key. A key stored beside
the deployable application does not establish an independent trust root.

## Safety boundaries

- Every path is relative and remains under the selected project root.
- Symbolic links are rejected.
- One PHP file is limited to 64 MiB.
- One snapshot is limited to 100,000 PHP files.
- `.git`, `.pam`, `node_modules`, `storage`, and `target` are excluded as
  mutable or unrelated runtime directories.
- PAM refuses a snapshot from another PAM version or native ABI.

Generate and sign a new snapshot after every PHP deployment. Never edit the
manifest independently from its sources.

Upstream PHP does not enable OPcache for Embed SAPI, so PAM does not market this
as a bytecode/heap snapshot. Source integrity plus deterministic page-cache
warming is the supported production contract.
