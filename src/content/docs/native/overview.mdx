PAM Native keeps PHP 8.4 alive and renders platform controls directly. Rust owns validation, reconciliation, diffing, and layout. Kotlin applies mutation batches to Android Views; Swift applies the same protocol to UIKit.

It is not a WebView and does not ship React's JavaScript runtime.

That sentence is not a branding technicality; it is the architecture. PAM
Native was built for teams that want the productivity and expressiveness of
PHP without accepting a browser surface or a JavaScript-driven imitation of
native UI. Lists recycle natively, gestures stay on the UI thread, media and
cache work live below the component API, and the platform renders the controls
users actually interact with.

We built the difficult path on purpose: one typed PHP authoring model, a
bounded binary protocol, a Rust rendering engine, and true platform views. That
is why PAM Native can aim for native behavior instead of merely resembling it.

```php
App::run(fn () => Screen::make(
    Column::make(
        Text::make('Checkout')->style(new Style(fontSize: 28)),
        Button::make('Pay')->onPress($pay),
    )->style(new Style(flexGrow: 1, padding: 24, gap: 16)),
));
```

## Authoring styles

Every public authoring style resolves to the same `Renderable → Element → PNT1/PNP1` path:

- explicit typed PHP trees;
- class components;
- functional components;
- declarative `.pam` views;
- single-file `*.pam.php` components; and
- generated custom native views.

Templates are parsed once, validated, and kept in memory. Expressions read component or data paths and do not use `eval`.

## Create and prepare an Android app

Install PAM once, then let the CLI own the project lifecycle:

```bash
pam init my-app --template mobile-ui --platform android
cd my-app
pam doctor --fix
pam doctor
pam dev
```

The repair command installs the release's checksum-verified PHP runtimes and
prebuilt native engines for `arm64-v8a` and `x86_64`. A normal application build
does not require a local Rust toolchain. Java 17 and the Android SDK remain
platform prerequisites and the doctor reports their exact missing components.

Install formatting, diagnostics, completion, hover, and navigation using the
[editor setup](./editor-tooling/) for VS Code, Neovim, Helix, or another
LSP-capable editor.

## Native component surface

The Android renderer includes layout, text, images, inputs, pressables, scrolling and recycled lists, modals, activity indicators, status bar control, keyboard avoidance, refresh control, Android-specific touch behavior, and system APIs.

The iOS renderer decodes protocol v1 mutation batches and maps the shared node surface to UIKit. It includes input, press, image, scroll/end-reached, refresh, drawer, modal, custom-view, runtime, storage, HTTP, and system bridges. See [iOS renderer](./ios-renderer/) for the exact implementation and current verification boundary.

Performance-sensitive behavior stays native: input cursor and selection, press feedback, scrolling, image loading, modal interaction, refresh gestures, animations, and view mutation commits do not require a round trip through PHP.

## Content-addressed application releases

Android installs the packaged PHP application into a content-addressed
directory under the app's private storage. A new bundle is written to a
temporary directory, validated, and atomically promoted before the runtime
starts it. The active directory is never mutated in place.

PAM Native 0.5.41 also prunes obsolete application releases asynchronously
after startup. It retains the active release and the newest inactive release as
a local rollback candidate. Cleanup does not run on the render path and never
deletes the active directory.

This bounds private-storage growth during repeated development installs and
production updates without adding work to the first native frame.

## Platform support

| Requirement | Contract |
| --- | --- |
| PHP | 8.4.x and 8.5.x selectable runtimes |
| Android | API 26–36 |
| PAM Native protocol | Version 1 |
| iOS | Generated UIKit host; PHP 8.4/8.5 simulator certification and signed IPA tooling |
